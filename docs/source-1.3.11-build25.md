## Included behavior

- Rich diary text: paragraph styles, inline emphasis, lists, quotes, undo, and inline photos, with reading/editing modes.
- Diary document and recovery storage reuse the vault data password and existing AES-GCM envelope; saving a legacy entry removes that entry's plaintext title/content copy.
- Single-diary PDF rendering uses selectable text, semantic styles, and intact embedded images. Export is gated by the existing VIP entitlement, owner/session authorization, and presentation generation before and after rendering and before sharing. The share provider receives an immutable in-memory snapshot.
- Native Back and edge-return handling flush drafts, preserve cancellation, and retain content-area text gestures. Adaptive layouts and asynchronous sensitive-result invalidation from the preceding release are included because they are archive inputs.

StoreKit products, prices, existing purchase/restore logic, and import allowance policy are unchanged from the prior public snapshot. No debug unlock or production entitlement change is added.

## Build and tests

Use Xcode 27.1 for the environment verified here. Open `ZeroNet-Space.xcodeproj`; use your own signing team for a physical device. No signing certificate or private key is supplied. A device-SDK compilation without signing can be run with:

```sh
xcodebuild -project ZeroNet-Space.xcodeproj -scheme ZeroNet-Space \
  -configuration Release -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/SealedPocket-Release CODE_SIGNING_ALLOWED=NO build
```

Run unit tests against a disposable simulator using its actual UDID:

```sh
xcodebuild -project ZeroNet-Space.xcodeproj -scheme ZeroNet-Space \
  -destination 'platform=iOS Simulator,id=<SIMULATOR_UDID>' \
  -derivedDataPath /tmp/SealedPocket-Tests -parallel-testing-enabled NO \
  -only-testing:ZeroNet-SpaceTests test
```

Diary UI tests deliberately require a disposable simulator named with the `SealedPocket-Demo-` prefix. They use the synthetic `Pocket7391` vault password, synthetic photo fixtures, and local StoreKit configurations. Photo tests need at least two synthetic images in that simulator's Photos library. The restart fixture needs prior normal password setup and therefore skips on a fresh vault. Do not run fixture/UI suites against personal vaults. The shared scheme's archive post-action advances the next build number after a successful archive.
